## 2. Mechanism of the fix

One pass, two products (`input_pointer.go`, `jsonStringScan`):

| product | space | consumer |
|---|---|---|
| `units []uint16` | UTF-16 code units | `unpairedSurrogates` → `repaired_at` (1-based, R4) |
| `badBytes []int` | **byte offsets** | `invalid_utf8_at` (0-based, R4b) |

An invalid byte is substituted by one U+FFFD **unit** and the walk continues, which is exactly what the decoder
does (one replacement per invalid byte) — so unit positions stay aligned with the string the agent received, and a
surrogate that follows a bad byte is still found. Pre-fix, the first bad byte aborted the scan: the mixed body in
§4 reported *neither* label, which is R4b's own secondary defect and is closed by the same change.

The byte offset is defined once, in the code and in the protocol comment: **0-based, into the caller's raw `text`
value, counted from the byte after the opening quote, escapes counted as written.** An invalid sequence is by
definition unescaped (a `\uXXXX` escape is ASCII and always well-formed), so the offset always addresses the
offending byte: `lit[off+1] == 0xff` is asserted, not asserted-by-comment.

Wire shape:

```
OUT {"success":true,"detail":{"transcoded":false,"encoding":"utf8","codepoints":3,
     "invalid_utf8_bytes":1,"invalid_utf8_at":[1]}}
```

## 3. Three shapes, three outcomes (`TestP14B05ThreeShapesThreeOutcomes`)

Bodies differ; the first two decode to the **same** Go string (`"a\ufffdb"`).

| shape | body `text` literal | detail labels | signature |
|---|---|---|---|
| caller-sent U+FFFD | `a\ufffdb` | none | `""` |
| lone surrogate | `a\ud800b` | `repaired_rune_count:1`, `repaired_at:[2]` | `"rune"` |
| invalid byte | `a\xffb` | `invalid_utf8_bytes:1`, `invalid_utf8_at:[1]` | `"byte"` |

The test computes each signature from key presence and asserts the three are pairwise different — not merely that
a key exists. §4's mixed body additionally proves the spaces do not collide: `invalid_utf8_at:[1]` (byte) and
`repaired_at:[3]` (code unit) in one response, in two keys.

## 5. Contract

Relied on, verbatim — `docs/contracts/P10-07_CONTRACT_V3_1.md:568`, §9.4:

> `encoding:"utf16"` means the caller supplies code units and probe must **not** re-encode: on Windows it emits
> them verbatim; elsewhere it decodes to UTF-8 first and reports `detail.transcoded:true`. **Never silently lossy.**

Two sentences: *"Never silently lossy"* is the only stated requirement over this class, and it already licenses
reporting through `detail`; repairing a byte the caller sent and saying nothing is precisely the failure the
sentence forbids, while no clause authorises refusing a string the backend can type. The contract was **not**
edited.

Contract defects recorded, not fixed:
1. The sentence names `detail.transcoded` as the report channel and gives no shape for a *repair*; both R4 and
   R4b had to invent keys. `detail` is open, so this is a gap in shape, not in permission.
2. §9.4 does not say which position space a report would use. This unit fixes byte offsets to the raw `text`
   literal (0-based); a caller whose body carries escapes before the bad byte will see an offset that is larger
   than its position in the decoded text. The offset still names the exact offending byte, and the definition is
   in the field comment, but the contract should pin the convention rather than each unit inventing one.
3. Line drift: P14B-02 cited this sentence at `:566`; in the current file it is `:568`. Same text.

## 7. Open items

1. **The offset space is the raw literal, not the decoded text.** With escapes before the bad byte the number is
   not the byte's index in the caller's text (§5 defect 2). Fixing that needs a decoded-byte walk — a second
   decoder, which R4's design deliberately avoided. Named, not absorbed.
2. **Other string params are not scanned.** `context` and `window` can carry invalid bytes and are repaired just
   as silently; §9.4 covers `text`, so they are outside this unit's brief.
3. **`child_close_verify.py` defaults `--repo` to `/opt/data/plugins/hermes_router`.** The brief's command therefore
   inspects the wrong repository; it was run with `--repo /opt/data/projects/PROBE_UPGRADE/v119wt` as well.
