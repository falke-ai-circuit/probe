composited refusal, and a full-screen capture on a composited seat still answers `200 source:"screen_region"` (screen
pixels are lifted from the root, so a compositor does not take them away).

## 7. Contract defects — recorded, not edited

1. **§10:612 names the compositor path but never says what a build without it answers.** §11:642's 501 row is the only
   licence, and its wording ("no implementation of the primitive") fits `NOT_IMPLEMENTED` at least as well as
   `NOT_EXPOSED` — both are in the same reason enum, and the two names tell an operator different things ("ship it" vs
   "this seat will never expose it"). Resolved to `NOT_EXPOSED` on three text signals: the review's reading of §11
   ("this deployment cannot obtain it"), §10:612's Wayland window cell which uses `NOT_EXPOSED` for exactly
   "no per-window cast", and `internal/agent/contexts.go:252`, which already advertises `capture.window` as
   `NOT_EXPOSED`. **The contract owner should rule which name a missing compositor path takes.**
2. **§10:600's `source:"compositor"` is unreachable in this build** — a documented label with no code path, the mirror
   image of R5's class. Not implemented here: the brief is the refusal, and the label needs
   `XCompositeNameWindowPixmap` plus a pixmap read (a separate unit).
3. **§10 contains no requirement to *detect* compositing.** R5's detection demand comes from the review and from
   §11:649's "500 tells the operator the agent broke", not from a §10 line. Recorded so the next reader does not hunt
   for it.
4. **Behaviour change that wants a ruling:** on a composited seat a window capture that used to answer
   `200 window_direct` now answers `501 NOT_EXPOSED`. Argued as correct — §10 requires the compositor path for a
   redirected window, so those pixels cannot honestly be labelled `window_direct`, and a 200 whose pixels are a
   different surface than the caller asked for is the failure mode R5 is about — but it is a refusal where pixels
   were previously returned. The gate is seat-level, not per-window, because redirect state is queryable only through
   XComposite, and on this host `NameWindowPixmap` cannot even answer (§4).

## 8. Open item

**UNPROVEN-ON-HOST:** a real compositor's `GetImage` error (BadMatch on a redirected drawable) cannot be produced here —
Xvfb accepts `CompositeRedirectWindow` and still serves the window (§4). The deterministic halves are covered: the
composited condition → 501 `NOT_EXPOSED` end-to-end on Xvfb, the mapper shape, and the negative legs. R5's *cure*
(`XCompositeNameWindowPixmap` → `source:"compositor"`) remains unimplemented by design; this unit closes the label, not
the capability.
