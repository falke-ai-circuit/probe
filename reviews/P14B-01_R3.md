# P14B-01 — R3 / §9.2: the gap echo can be wrong, and now it is caught

**Unit:** P14B-01 · workflow wf_probe1 · repo `/opt/data/projects/PROBE_UPGRADE/v119wt` · branch `r119-build`
**Parent:** 62865d7 (baseline 743 pass / 0 fail / 2 skip, reproduced here before any edit)

## The residual, and what changed

The old acceptance measured `gap := inj.times[3].Sub(inj.times[1])`, asserted it `<= defaultDoubleClick/2`
and `>= multiClickGap/2`, then asserted `res.GapMS == gapMillis(gap)`. Every term derived from the same
injected constant (120 ms) and `gapMillis` rounds, so `sleep(120); return 120` satisfied all three. The
echo could not be wrong, which means it was not proven to be an echo.

Two changes make it falsifiable:

1. `internal/agent/input_pointer.go` — the press stamps are taken **after** `inj.Button(button, true)`
   returns, i.e. when the event is on the wire, not before the call. A seam that costs time at the wire now
   widens the measured interval, so the echoed number has something to disagree with.
2. `internal/agent/p1402_input_test.go` — the fake seam (`fakeInput.latency`) books a real
   per-press cost, stamped at return. With a 25 ms/press seam the perceived interval is materially larger
   than the nominal spacing, and the test asserts `gap_ms == gapMillis(measured)` **and**
   `gap_ms != gapMillis(nominal)`.

## 400 ms is a fallback, not a universal (requirement 3)

Plumbing status, plainly: the JSON config (`cmd/probe/config.go`, `UnifiedConfig.ClientConfig`) has **no**
double-click key, and adding one would edit a file this unit's scope excludes. So the smallest honest
version was used: `agent.Config.DoubleClickMS` (0 = not configured) → resolved once in `New()` into
`Agent.clickWindow` → `effectiveClickWindow()` → `clickSpacing(window) = window × 3/10`. The spurious
`multiClickGap` literal is gone from the gesture (`multiClickGap` survives only as a computed value for the
Windows `multiClicker` path's documentation of the default), and the spacing is derived at every call site.

Assertion (not a description): a seat configured at `seatWindow := 200 * time.Millisecond` →

```
default window:    window=400ms spacing=120ms measured gap=160.854357ms gap_ms=161
configured window: window=200ms spacing=60ms measured gap=101.666508ms gap_ms=102
```

`seat.GapMS (102) < seatMS (200)` — compared against the configured value, never a literal — and
`seat.GapMS < def.GapMS`, plus `seat.GapMS ≈ gapMillis(clickSpacing(seatWindow)) + 2×gapMillis(latency)`.
